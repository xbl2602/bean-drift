# 给前端：直接用 NASA 现成的月面瓦片做 2D 底图

> 写给 `ShanLe1224`（product page）。调研人：`xbl2602`（Claude Code 协助）。
> **状态：已实测能取到瓦片，但使用条款没查到、一部分细节没验证（见第 6 节）。** 不要当成"官方保证"。

## 1. 一句话

2D 全月图的**底图画面**不用我们自己切块：NASA Moon Trek 有现成的、浏览器能直接跨域读的瓦片，最细约 **83 米/像素**。你可以直接拿来铺底图，省掉大量工作。

但它**只是一张照片**，不能用来算坡度、光照、遮挡。那些由我们另外提供（第 5 节）。

## 2. 可以直接用的图层

| 用途 | 图层名（Layer） | 格式 | 最高级别 | 约多少米/像素（赤道） |
|---|---|---|---|---|
| **推荐：底图（照片）** | `LRO_WAC_Mosaic_Global_303ppd_v02` | JPEG | 8 | 约 83 |
| 地形渲染（彩色） | `LRO_LOLA_ClrShade_Global_128ppd_v04` | PNG | 5 | 约 666 |
| 地形渲染（灰度） | `LRO_LOLA_DEM_Global_128ppd_v04` | PNG（**8 位灰度**，不是真实高度） | 5 | 约 666 |

我实测过：WAC 第 8 级能取到，第 9 级返回 404；LOLA 两个图层第 5 级能取到，第 6 级返回 404。

## 3. 地址规则（这三项已实测）

```
https://trek.nasa.gov/tiles/Moon/EQ/{Layer}/1.0.0/default/default028mm/{z}/{row}/{col}.{jpg|png}
```

例：`https://trek.nasa.gov/tiles/Moon/EQ/LRO_WAC_Mosaic_Global_303ppd_v02/1.0.0/default/default028mm/0/0/0.jpg`

- **投影**：等距柱状（经纬度直接展开，`EPSG:104903`）。经度 -180° 到 180°，东经为正，纬度 -90° 到 90°。
- **瓦片大小**：256×256 像素。
- **编号**：从左上角（经度 -180°、纬度 90°）开始，**第 0 行在北边**。第 `z` 级共 `2^(z+1)` 列 × `2^z` 行。第 0 级是 2 列 1 行。
- **每个图层的准确范围**以它自己的描述文件为准：
  `https://trek.nasa.gov/tiles/Moon/EQ/{Layer}/1.0.0/WMTSCapabilities.xml`
- 目录列表是禁止访问的（403），不能靠浏览目录找图层，只能靠上面的描述文件。

## 4. 浏览器能不能直接读

- 实测返回头里有 `Access-Control-Allow-Origin: *`，**可以从我们的网页直接跨域读**，不用经过我们的服务器。
- 支持 HTTP 范围请求（`Accept-Ranges: bytes`）。
- 用 three.js 的贴图加载时，记得设成匿名跨域（`crossOrigin = 'anonymous'`），否则贴图会被浏览器当成"污染"的而无法在 WebGL 里用。

> 💡 **候选做法（我没验证过，仅供参考）**：Leaflet 的 `L.CRS.EPSG4326` 默认就是"第 0 级 2×1 瓦片、256 像素"，和这里的规则对得上，可能可以直接铺。如果你用 three.js 自己铺在平面或球面上，就按第 3 节的编号规则自己算要取哪几块。

## 5. 它做不到的（这些由我们另外提供）

| 你可能想要 | 为什么现成瓦片不行 | 怎么办 |
|---|---|---|
| 真实高度、坡度 | 灰度图只有 256 级，不是真实高度值 | 我们自己做 16 位高度瓦片（还没做） |
| 某个日期时间的明暗 | 照片的光照是**拍摄那一刻固定的**，不会随时间轴变 | 用 `/api/point` 实时算太阳方位和高度；明暗图层由我们预计算后提供 |
| 日照时间图、通信图层、坡度图 | 现成瓦片里没有 | 我们自己预计算，格式和地址定了会写进 `docs/SHARED_INTERFACES.md` |
| 第一人称视角的细节 | 精度差了一两个数量级 | 同第一行，用我们自己的高精度数据 |

**拿"点击位置的参数"请调用我们自己的接口**（见 `docs/SHARED_INTERFACES.md`），不要自己算星历：

```
GET /api/point?latDeg=-89.71&lonDeg=62.5&time=2030-01-01T12:00:00Z
```

## 6. 风险与还没确认的事

1. **使用条款没查到。** NASA 的 Trek API 页面只写了 "© 2016 Trek"，没有限流、署名或禁止直连的说明。是否允许在比赛作品里直接引用，**未确认**。
2. **不保证一直可用。** 这是 NASA 的服务器，不是我们的。比赛当天它慢了或挂了，我们没法处理。所以：
   - **请把图层名和地址集中放在一个配置文件里**（别散在各处写死），以后好整体换成我们自己镜像的地址。
   - 加载失败时要有降级（显示一张低精度的本地图，或者提示"底图加载失败"），别让整个页面崩掉。
   - `xbl2602` 会把低层级瓦片镜像一份到我们自己的存储作为备份（还没做）。
3. **有一处我解释不了**：WAC 第 1 级应该只有 4 列（0–3），但请求第 4 列也返回了 200（可能是服务器返回空白瓦片）。请求时用描述文件里的范围算，别靠"返回 200 就是有数据"来判断。
4. **极区图层没研究**。描述文件里还有另一套极区网格（`5×3` 起），我没查它的用法。南极相关画面请先别用，等我们的高精度数据。
5. **比赛要求**：用 NASA 数据有加分，**视频里要说明**；用了就要在 `docs/CREDITS.md` 里登记（我已先登记了一行，标注"条款未确认"）。
