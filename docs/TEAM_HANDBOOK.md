## 2. 第一天要做的事（每个人）

1. 有 GitHub 账号；接受这个仓库的邀请（仓库地址由 `xbl2602` 提供）。
2. 装好你要用的 AI 工具（Claude Code / OpenCode / ChatGPT Codex / DeepSeek harness 任选，团队都兼容）。
3. 把仓库下载到电脑（`git clone`，步骤见 [GIT_GUIDE.md](GIT_GUIDE.md)）。
4. **建你的身份文件**：把仓库根目录的 `IDENTITY.example.md` 复制成 `IDENTITY.md`，填上你的 GitHub 用户名、角色和负责的目录（让 AI 帮你填也行）。它只在你自己的电脑上，不会提交；AI 靠它知道"你是谁、能改哪些文件夹"。
5. **让你的 AI 先读 `AGENTS.md`**，然后读 `docs/PROJECT_CONTEXT.md` 和 `docs/FEATURE_SPEC.md`。你自己也读一遍 FEATURE_SPEC，知道我们要做什么。
6. 做一次"热身提交"：在 `docs/logs/<你的用户名>/` 里让 AI 帮你写一个 `YYYY-MM-DD.md`（内容："我今天学会了..."），走完 [GIT_GUIDE.md](GIT_GUIDE.md) 的完整流程（分支 → 提交 → 推送 → PR）。这一步的目的是**把流程走通一次**，内容不重要。

## 3. 日常怎么干活

1. **开工前**：`git pull` 拿最新（让 AI 做也行）。
2. **每个任务一个分支**：分支名 `<你的用户名>/<区域>-<任务>`。
3. **一次只让 AI 做一件事**，做完你看结果（打开网页、看截图），不对就**具体地**说哪里不对（"左下角那块比旁边大三倍"，不要说"不好看"）。提示词怎么写见 [AI_PLAYBOOK.md](AI_PLAYBOOK.md)。
4. 做完一块能运行的东西就**提交并推送**，开 PR，通知 `xbl2602` 来审。
5. 收工前在 `docs/logs/<你的用户名>/` 留一句话：做了什么、没做完什么。
6. 同时开多个 AI：每个 AI **一个分支加一个独立文件夹**（`git worktree`，见 GIT_GUIDE），**两个 AI 绝不改同一个文件**。

## 4. 卡住了怎么办

- **AI 说要改你不负责的文件夹** → 别让它改，告诉 `xbl2602`。
- **出现"冲突（conflict）"或不认识的 git 报错** → **停下来**，别让 AI 自己"想办法解决"，截图发给 `xbl2602`。
- **AI 要你输入密钥/密码** → 不要输入，不要把密钥贴给 AI，告诉 `xbl2602`。
- **不知道某个功能该怎么做/要什么效果** → 先看 `docs/FEATURE_SPEC.md`，没写的问 `xbl2602`，不要让 AI 瞎猜。
- **搞乱了、不知道现在是什么状态** → 不要自己乱敲命令。只要提交过，东西就丢不了。截图问人。
