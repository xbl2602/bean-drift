# 数据流规则（DATA_FLOW）

> 目的：数据**只能按固定入口、固定方向流动**，这样 5 个人 × 多个 agent 同时开发时，口径不会各写各的。强制版本是 AGENTS.md 第 5.2 节。

## 1. 流向（单向）

```
原始数据 data/raw/（NASA，大文件，不进 git）
   │  只被 pipeline/ 读取
   ▼
pipeline/（xbl2602 的个人电脑上运行）
   │  产出：衍生数据 + manifest（版本、来源、处理参数、生成时间）
   ▼
衍生数据（静态文件：图块、地平线图、统计图、预设点）
   │  只被 src/core 的数据接口读取
   ▼
src/core 统一数据接口
   │
   ▼
logic/ → api/ · mcp/ · ui/ · agent 工具
```

## 2. 规则

1. **前端和各功能模块不直接读原始数据，也不直接读衍生数据文件**，一律经 `src/core` 的数据接口。想要新的数据，找 `xbl2602` 加接口。**唯一的例外（2026-11-14）**：整月图层（`public/data/v1/` 下带 `manifest.json` 的静态文件）可以由网页直接按静态文件读，因为一次要渲染上百万个格子，不可能逐点走 API；读法以 `manifest.json` 为准（见 SHARED_INTERFACES 2.5.1），不要自己猜格式。单点的数值仍然只走统一接口。
2. **不重复实现天文与地形计算**：星历、地平线、可见性只有一份实现，放在 `src/core`（或 `pipeline` 的预计算），别处调用。
3. **每份衍生数据都带 manifest**：数据源、分辨率、投影、处理脚本与版本、生成时间。没有 manifest 的数据不得被使用。
4. **所有对外返回的数值都带单位、坐标系和数据来源**，不要让调用方猜。
5. **在边界处校验输入**：API、MCP、agent 工具的入口，经纬度范围、时间格式、点数上限都要检查，拒绝时返回看得懂的错误。
6. **公开接口默认只读**。写操作必须单独声明并经 `xbl2602` 批准。
7. **agent 窗口不直接碰数据**：它只能调用与 MCP 相同的白名单工具。
8. 密钥永远不在数据流里出现（见 AGENTS.md 第 4 节）。

## 3. 约定（单位、坐标、时间）

> 这是**建议的统一约定**，`xbl2602` 确认后写入 `docs/SHARED_INTERFACES.md` 作为强制标准。在那之前如果你的代码需要约定，**以这里为准并在 PR 里注明**。

| 项 | 约定 |
|---|---|
| 经纬度 | 月面经纬度（度），**东经为正**，纬度北正南负；字段名 `latDeg`、`lonDeg` |
| 高度 | 米，相对参考球 **1737.4 km**（与原型一致）；字段名带 `M` 后缀 |
| 坡度/角度 | 度；字段名带 `Deg` 后缀 |
| 时长 | 小时；字段名带 `H` 后缀 |
| 时间 | **UTC**，ISO 8601（`2030-01-01T00:00:00Z`）；内部可用毫秒时间戳，对外一律 ISO |
| 方位角 | 罗盘方位：正北 0°，向东增加（与原型一致） |
| 地形分辨率 | 返回里说明"这个值来自多少米/像素的数据" |

## 4. 预计算产物放哪

**当前（2026-11-14 起）**：整月 0.25° 预计算（地形、地平线、一年统计，约 55 MB，最大单文件 34 MB）放在 **`public/data/v1/`，进 git，随 Vercel 部署**。文件格式和缩放系数写在同目录的 `manifest.json`，怎么重算见 `pipeline/README.md`，决定背景见 `docs/decisions/2026-11-14_xbl2602_precomputed-terrain-and-year-stats.md`。

- 服务端（API、MCP、agent 工具）经 `src/core/data/precomputed-maps.ts` 用文件定位读取，只读单点附近的几个字节；`next.config.ts` 的 `outputFileTracingIncludes` 负责把文件打进函数包。
- 网页图层按静态文件取（同源，走 Vercel 静态资源，不占函数）。
- 数据文件带版本目录（`v1`）；格式改变时新建 `v2`，不要原地改。

**仍待决（见 TODO Q4）**：更高分辨率的数据（全月 118 m DEM 约 8.5 GB、着陆点尺度的区域数据）放哪。候选：Cloudflare R2 / VPS 静态文件 / Supabase Storage；选择时要考虑单文件大小限制、总量、访问速度、VPS 宕机的影响（演示用数据应能脱离 VPS 访问）。
