## 原因

- 一个 main 说了算：线上是什么，main 就是什么，不再有"做了但没上线"的东西。
- 分支各自继续往前走，越晚合越难合；现在每个分支领先 main 只有几个提交，冲突最小。
- 文档和代码不一致本身就是 bug（AGENTS.md 第 14 节），趁这次一起修。

## 备选方案

- 逐个 PR 合：每个都要等 CI 和 Vercel 预览，慢，而且相互之间有先后依赖（比如 #31 改了 AI 白名单和 `registry.ts`）。一次合完、一次验证更稳。
- 压成一个提交（squash）：会让 contributors 里看不到夏娜、chanjy0806、louis068 的提交，不选。
- 只合 #31，其他让各人自己开 PR：夏娜和 chanjy0806 的分支都没有 PR，新手不一定知道要开；而且他们的内容是 xbl2602 想要的。

## 怎么对齐（给每个人，大白话）

1. **先存好你手上的东西**：`git status` 看有没有没提交的改动。有就 `git add <你改的具体文件>` 再 `git commit`（或者先问 xbl2602）。**不要用 `git add .`。**
2. `git fetch origin`，看到 main 更新了。
3. **不要在旧分支上继续**。从最新 main 开新分支：`git switch -c <你的用户名>/<区域>-<新任务> origin/main`。
4. 如果你的旧分支里有**还没合进 main 的提交**：先问 xbl2602 那些提交在不在这次合并里（ShanLe1224、chanjy0806、louis068 的上述分支都已合入，不用再管）。不在的，用 `git cherry-pick <提交号>` 一个个搬到新分支上；搬不动就停下来找 xbl2602。
5. 旧分支留着别删，等 xbl2602 确认后统一清理。
