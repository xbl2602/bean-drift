# 功能规格（FEATURE_SPEC）

> 状态：草案，由 `xbl2602` 口述 + 第一次线下会议手写导图（`docs/meetings/offline-meeting-1_mindmap.md`）交叉整理。
> **这是"想做什么"，不是"已经定了怎么做"**：带 ❓ 的是需要团队确认的点，带 💡 的是 AI 提的候选方案，都还没拍板。
> 范围结论：**只做"完整版"**。简易版（给新手降低门槛）是后续设想，本次不做。

## 1. 用户与使用流程

用户分三类（导图）：**技术人员、教育者、公众**。同一个作品要让三类人都能用，完整版里靠"信息分层"（先给直观结果，再展开细节）实现，而不是做两个版本。

**使用主线：**

1. 进入网站 → **landing page**（讲清楚这是什么、为什么重要、一眼看到最震撼的画面）。
2. 点进入 → **product page**。首屏是**整个月面的二维展开图**，下方有**时间轴**，拖动可看到光照变化。
3. 选图层 → 鼠标悬停看十字线 → 点击看完整参数 → 需要时切第一人称视角 / 多点对比 / 问 agent。

导图里的 30 秒 pitch 流程（可作为视频分镜骨架）：① 输入任务时长、功率需求 ② 选站点（列表/坐标）③ 选日期时间（输入/日历）④ 展示光照与地球条件 ⑤ 展示太阳与地球位置 ⑥ 展示关键日期 ⑦ 进度更新。

## 2. 核心问题（赛题本身）

- **阳光** → 太阳能发电；**看得到地球** → 对地直连通信。选址要**同时满足两者**。
- 影响因素：山、坡度、坑洞（导图手写"山 / slope / 洞"）；月球天平动（导图写了"月球摆动 ⇒ communication"，❓手写不太清，按天平动理解）。
- 要回答的问题：断电会持续多久？断信号会持续多久？一年里最坏的一次是多久？能不能找到同时满足的位置？
- 月球**没有大气**：没有折射，地平线只由地形和月球球体边缘决定；太阳视半径约 0.27°，地球视半径约 1.9°（核对数值再用），要处理**部分遮挡**。

**术语（先统一说法，避免各写各的）**

- **断电** = 太阳被地形地平线遮住（太阳不可见）的连续时段。
- **断信号** = 地球被地形地平线遮住（地球不可见）的连续时段。
- **月昼/月夜** = 太阳在月面某点的一次"出–落"周期，约 29.5 地球日。

## 3. 二维展开图与图层

**范围：整个月面，且"每一个点都能取到数据并可被调用"**（口述要求）。这决定了数据策略，见第 6 节。

| 编号 | 图层 | 说明 | 计算类型 |
|---|---|---|---|
| L1 | 纯地图 | 底图（反照率/地形着色），无光照 | 预计算静态 |
| L2 | 光照与阴影 | 按当前时间的真实太阳位置，带山体阴影 | 随时间变化（时间轴驱动） |
| L3 | 高度地形图 | 海拔高度着色 | 预计算静态 |
| L4 | 一年内最长单次断电时间 | 势能图风格，带等高线；**越绿越短，越红越长** | 预计算（重） |
| L5 | 一年内最长单次断信号时间 | 同上配色 | 预计算（重） |
| L6 | 一年内最长平均断电时间 | ❓指标定义待确认，见下 | 预计算（重） |
| L7 | 一年内平均单次信号时间 | ❓指标定义待确认，见下 | 预计算（重） |
| L8 | 坡度图 | 由高度数据导出。口述里"好像和高度图重复"：数据同源，但视觉用途不同（选址要看坡度阈值），**建议保留，成本很低** | 预计算静态 |
| L9 | 综合有效位置图 | 按用户设置的基地参数着色（见第 5 节） | 前端实时组合预计算结果 |

**❓ L6 / L7 指标定义（口述含糊，必须先定）**

- "最长平均断电时间"可能指：(a) 一年里每次断电的**平均时长**；(b) 每个月昼周期里断电时长的最大值再取平均；(c) 其他。
- "平均单次信号时间"可能指：一年里每次**连续有信号时段**的平均时长。
- 定义不同，要预计算的东西不同。**写代码前先在 `docs/decisions/` 定下精确公式**，并在 UI 的图例里原样写出来。

**交互**

- 鼠标悬停：**十字线跟随**，作为视觉引导（并显示悬停点的经纬度和当前图层的值）。
- **单击一次左键**：弹出该处完整参数卡（见第 4 节）。
- 经纬度输入：除鼠标外，支持直接输入经纬度定位。
- **多选与对比**：可选多个点，并排对比参数。
- 按钮切换到该点的**第一人称视角**（已有原型：`prototypes/lunar-scene-demo/`）。
- 时间轴：可拖动；多档时间尺度（原型里已验证"自转/月相/公转/长周期"四档，见 PROJECT_CONTEXT）。

## 4. 点位参数卡（单击后显示）

高度、坡度（及坡向）、经纬度、当前太阳与地球的方位角/高度角、距日落/地球落下的剩余时间、一年内日照比例和地球可见比例、最长单次断电/断信号、各月昼窗口、地平线剖面（方位角→遮挡仰角）、关键日期。（精确字段表见 `docs/SHARED_INTERFACES.md`，以那里为准。）

## 5. 基地参数与综合有效位置图（L9）

用户输入自己的基地需求，系统给整个月面着色。导图第 1 步是"输入任务时长和功率"。候选参数（❓待确认）：任务持续时间、功率需求、可容忍的最长断电时间、是否需要直连地球通信及可容忍的最长断信号、最大可接受坡度、最低日照比例。着色规则要**可解释**（能说清为什么这个点是红色）。

## 6. 数据策略（"全月每点可调用"怎么做）

> 💡 以下是 AI 提的候选方案，**可行性和耗时未验证**。第一个任务就是在 `xbl2602` 的电脑上量一下算一块区域要多久，再决定。

- 公开全月高度数据的分辨率大约在百米量级，两极更细（见 `docs/PROJECT_CONTEXT.md` 第 5.4 节）。**整月每个像素都算一年统计量很重，所以分层：**
  1. **预计算静态图块**：高度、坡度、山体阴影底图，多级缩放（地图那种"放大越清楚"的切片）。
  2. **预计算"地平线图"**（💡）：每个像素存若干个方位上的遮挡仰角。有了它，任意时刻的"太阳/地球是否可见"都只是一次比较，**时间轴拖动可以直接在显卡里实时算**，一年统计量也能由它导出。
  3. **按需精算**：用户点任意一点，用该点附近的高分辨率数据和星历现场算出精确参数卡（原型里已有 `horizonProfile` 与 `skyAtLonLat`）。这一层保证"每一个点都能调用"，哪怕预计算图块较粗。
- 重计算在 `xbl2602` 的个人电脑上跑，产物是静态文件；放哪里（Vercel / Supabase Storage / VPS）待定，见 TODO。
- **月球背面**大部分区域永远看不到地球（只有靠近边缘处受天平动影响时有时无），这是真实现象，UI 要明确说明，不能显示成 bug。

## 7. 预设点位

提供一批预设点，用**中国、美国、俄罗斯（苏联）等著名航天器着陆位置**。例子（❓具体清单待定）：阿波罗系列、嫦娥系列、月球号系列、CLPS 目标。**坐标必须从可靠来源查证，不得凭记忆填写**，来源记进 `docs/CREDITS.md`。现有原型里只有南极和阿波罗 11 号有真实高精度地形。

## 8. Agent 窗口

- 用自然语言操作软件：例如"找出一年里最长断电不超过 50 小时的平坦位置"、"对比阿波罗 11 号和嫦娥三号"。
- LLM 只接 **DeepSeek**，由 `xbl2602` 在服务端配置，**用户不能填 key**（见 AGENTS.md 第 4、6 节）。
- agent 只能调用与 MCP 相同的**只读白名单工具**。

## 9. API 与 MCP

- **API**：获取软件里的各项参数（点位参数、对比、预设列表、时间序列等）。
- **MCP**：让外部 AI agent 无缝操作这个软件（HTTP/SSE 传输）。
- 两者与网页、agent 窗口共用同一份 `logic/`。工具与接口的精确定义写进 `docs/SHARED_INTERFACES.md`。

## 10. 部署与分发

要支持：**Docker、API、MCP、Vercel、本地安装**，且**零环境依赖、零污染**。现阶段不需要真的上 Vercel。规则见 AGENTS.md 第 5.3 节。

## 11. 已有原型能做什么

`prototypes/lunar-scene-demo/`：南极（真实 LOLA 10 m）和阿波罗 11 号（真实 LROC NAC 2 m）两个站点的**第一人称场景**，1.6 m 眼高，真实星历驱动太阳/地球/星空，时间拖条，地平线遮挡窗口条，远处阴影随时间重算。**没有**二维展开图、图层、点位参数卡、多点对比、agent、API、MCP。
